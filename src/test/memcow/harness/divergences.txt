# divergences.txt --- the REGISTERED, DOCUMENTED ways memcow output may differ
#                     from stock md output.
#
# Plan §7.1's gate is "regression subset zero diffs".  Memcow does not quite
# achieve zero: a small number of core SQL functions read relation files with
# stat() instead of going through smgr, so under memcow they measure the
# (empty) runtime PGDATA rather than the seed plus the overlay.  Those
# divergences are real, they are understood, and they have file:line citations
# below.  Everything else must be byte-identical.
#
# This file exists so that such a difference shows up in the gate as a NAMED
# allowance with a justification attached, rather than as a mystery diff that
# whoever reads the log next has to re-derive.  A diff hunk that no rule here
# explains fails the gate, and so does a rule that is claimed for a test but
# never actually matches (see --allow-engine-divergence in diff_engines.sh):
# a stale allowance is how a gate quietly stops testing anything.
#
# Format: three TAB-separated fields per line.
#
#     name <TAB> python-regex <TAB> justification
#
# The regex is matched (re.search, case sensitive) against the FULL TEXT of a
# unified-diff hunk -- context lines included -- because the SQL that produced
# a differing result is context, not a changed line.  Blank lines and lines
# beginning with '#' are ignored.
#
# Portions Copyright (c) 2026, PostgreSQL Global Development Group

dbsize_relation_size	pg_(relation|table|indexes|total_relation)_size\b	calculate_relation_size()/calculate_toast_table_size() stat() the path from relpathbackend() directly (src/backend/utils/adt/dbsize.c:326-348) instead of asking smgr, so under memcow they measure the runtime PGDATA -- which holds no relation files at all -- and report 0 for anything served from the seed or the overlay.  Confirmed by measurement: SELECT pg_relation_size('public.events'), count(*) FROM public.events yields 0|4000.  This is contract ADDENDUM item F, and it is the whole of the currently known memcow-vs-md output divergence.
dbsize_database_size	pg_database_size\b	calculate_database_size() walks the database directory in the running PGDATA with ReadDir() (src/backend/utils/adt/dbsize.c:107-165).  Same root cause as dbsize_relation_size: relation storage under memcow is the seed plus a DSA overlay, neither of which is a file under DataDir.

# tablespace_not_empty_check used to be a rule here, and a HAZARD rather than
# a reporting difference: DROP TABLESPACE decided emptiness by scanning the
# tablespace directory (destroy_tablespace_directories() ->
# directory_is_empty(), src/backend/commands/tablespace.c), which under memcow
# never holds a relation file, so the DROP succeeded -- removing the catalog
# row while the relations it held were still live in the overlay.  FIXED:
# DropTableSpace() now asks memcow_tablespace_in_use() first, which walks every
# database's overlay and the seed's pg_tblspc/<oid>/, and refuses exactly where
# md does.  The regress `tablespace` test is byte-identical between engines
# again and slice case S9 pins the refusal.  The rule is removed rather than
# kept, because a rule that no longer matches anything is exactly the
# staleness this file exists to prevent.
